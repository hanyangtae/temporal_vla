0. 결정
═══════════════════════════════════════════════════════════════════

**기준 개정 승인. drawer_right G2 통과 처리해도 된다.**

사전 등록 조건 중 "unseen scene 의 식별 정보까지 지워질 것"은 원리적으로
달성 불가능한 요구였음이 이번에 밝혀졌다(§2-A). 조건 오설계이므로 개정한다.

단 아래 §2·§3 을 문서에 반드시 반영할 것. **통과 사실보다 이번에 드러난
두 가지 발견이 더 중요하다.**

═══════════════════════════════════════════════════════════════════
1. 개정된 판정 기준 (이 문구로 32 문서에 명시)
═══════════════════════════════════════════════════════════════════

  G2 통과 = (a) **부분공간 추정에 포함된 scene 기준**으로 scene 식별력이
            유의하게 떨어지고, (b) 그 제거 후에도 within-scene succ/fail
            read 가 exp5-3 기준선(L12 AUROC ≥0.85, 창 38) 이상으로 살아남는다.

  ★ 통과의 의미를 좁게 적을 것: "fit 에 포함된 scene 에 한해, scene 성분을
    계산으로 제거해도 실패축이 살아남는다." 이후 문서에서 **"scene 은 제거
    가능하다"로 확대 인용 금지.**

═══════════════════════════════════════════════════════════════════
2. 반드시 문서에 남길 발견 2가지
═══════════════════════════════════════════════════════════════════

[A] **모델은 scene 을 "외운다" — scene 방향은 scene-특이적이라 전이되지 않는다.**

  근거(fold-wise scene probe, 평가 scene 을 부분공간 추정에서 제외):
      제거 전              0.989   (우연 0.05)
      linear_between r16   0.911
      linear_between r19   0.994   ← 19개 방향을 전부 지워도 안 지워짐
  20개 scene 의 평균이 만드는 방향을 전부 제거해도 held-out scene 은 여전히
  91~99% 로 식별된다. **새 scene 의 방향은 기존 scene 들이 span 하는 공간 안에
  없다.** 즉 SAE/선형이 잡아낸 scene 성분은 조합적 속성(레이아웃 요소·재질 등)이
  아니라 **scene 별 암기 방향**이다.

  이 사실은 각주가 아니라 **결과 절에 본문으로** 쓸 것. 이후 모든 설계를
  제약한다(§4 참조).

[B] ★**SAE 가 단순 선형보다 못했다 — 이번 라운드 최대의 정보.**

  같은 데이터·같은 layer(L12)·같은 read 프로토콜에서(token_agg=future):

    arm                    read AUROC(전체)   scene_probe(제거 검증)
    raw (제거 전)             0.800              0.767
    SAE top10/20/40/all      0.804              0.697~0.725   ← 거의 안 지워짐
    linear_between r12        0.889              0.339
    linear_between r16      **0.900**            0.339
    linear_between r19        0.898              0.339

  SAE selective feature 제거는 **scene 을 거의 못 지웠고 read 도 그대로**였다.
  성과를 낸 것은 **scene 평균 부분공간을 사영 제거한 선형 arm**이다.

  exp5 라운드 전체의 기획이 "SAE 로 scene 을 분리한다"였으므로, 이 결과는
  **기획 전제에 대한 직접 반증 증거**다. 반드시 32 문서에 표로 남기고,
  "SAE 를 계속 쓸 이유가 무엇인가"를 명시적으로 논할 것. 이걸 안 적으면 다음
  라운드가 근거 없이 또 SAE 로 간다.

  (G1 은 여전히 유효하다 — SAE feature 가 scene 을 **읽을** 수는 있었다.
   실패한 것은 그 feature 를 **지우는** 것이다. read 와 write/removal 의
   비대칭을 문서에 구분해 쓸 것.)

3. 보고 수치 정정 요구 (3건)
═══════════════════════════════════════════════════════════════════

[3-1] **판정 범위와 보고 수치가 어긋난다.**
  json 의 `verdict_scope` 가 `unseen_scenes` 인데, 보고된 0.88~0.90 은
  전체 scene 값(`window_mean`)이다. 판정 범위 값은:

    arm                    전체 scene        unseen scene(판정 범위, n=6)
    linear_between r12     0.889 (z 5.30)    0.801 (z 2.45)
    linear_between r16     0.900 (z 4.91)    0.808 (z 2.60)
    linear_between r19     0.898 (z 4.56)    0.793 (z 2.80)

  unseen 범위에서는 **z 가 전부 3 미만**이고 0.85 기준도 못 넘는다.
  → 32 문서에는 **두 범위를 나란히** 적고, 어느 쪽으로 판정했는지 명시할 것.
    개정 기준(§1)은 (a) 를 seen scene 기준으로 바꾸는 것이므로 전체 scene 값을
    쓰는 것이 정합적이나, **unseen 값이 약하다는 사실을 숨기지 말 것.**

[3-2] **"scene 식별 0.81 → 0.16" 의 출처를 밝힐 것.**
  대시보드가 연 산출물에는 그 값이 없다. 가장 가까운 것이 scene_probe
  0.767 → 0.339 다. 새 실행 결과라면 파일 경로를, 아니면 수치를 정정할 것.

[3-3] **mixer 는 이번 판정에 포함되지 않는다.**
  g2_mixer_L12.json 은 전 arm 이 `no_baseline_separation` — raw 의 read z 가
  2.61 로 제거 전 기준선부터 미달이다. **이번 G2 통과는 drawer_right 단독**
  이라고 명시할 것. mixer 는 peak layer 가 L2 이므로(exp5-3 §1) L12 로 판정한
  것 자체가 부적절할 수 있다 — L0/L2 로 재실행 후 판단.

═══════════════════════════════════════════════════════════════════
4. 추가 계산 (전부 기존 데이터, 수 분~10분)
═══════════════════════════════════════════════════════════════════

[4-1] ★**scene 간 방향 일관성(cos) 제거 전/후 비교** — 우선순위 최상.
  exp5-3 실측: scene 별 실패방향끼리 cos 평균 0.343(공통 성분이 소수).
  scene 성분 제거 후 이 cos 가 올라가는가?
    · 올라감 → 잔차화가 **steering 입력으로서의 방향을 개선**했다 = G3 로 갈 실익
    · 그대로 → 지우긴 했으나 방향은 나아지지 않았다 = G3 기대치 대폭 하향
  G2 의 목적이 둘(축 생존 · 방향 개선)인데 지금 보고에 후자가 없다.
  **이게 LOSO 부호 지표보다 중요하다.**

[4-2] **실패 신호가 1차원인가 부분공간인가.**
  r̂ 성분을 사영 제거한 뒤 잔차로 succ/fail 이 여전히 갈리는지 본다.
    · 안 갈림 → 1차원 → 성분 제거/고정 스텝이면 충분, 다차원 연산자 불필요
    · 갈림   → 부분공간 → conceptor 또는 SAE feature 집합이 처음으로 정당해짐
  G3 연산자 선택의 갈림길이다.

[4-3] LOSO 부호 지표(12/13 형식) 산출 — exp5-3 표와 형식을 맞추기 위해.

[4-4] read 가 0.800 → 0.900 으로 **오른** 이유 한 줄 진단.
  제거로 정보가 줄었는데 분리가 좋아진 것은 "scene 분산이 nuisance 였다"로
  설명되나, 확인 없이 단정하지 말 것. r 을 늘릴수록 단조 상승인지 확인
  (r1 0.836 / r4 0.858 / r8 0.866 / r12 0.889 / r16 0.900 / r19 0.898 →
   r19 에서 꺾임. 과제거 지점이 있는지 기록).

═══════════════════════════════════════════════════════════════════
5. 다음 단계 방향 (G3 설계)
═══════════════════════════════════════════════════════════════════

[5-1] **온라인 잔차화는 포기한다.** §2-A 때문에 추론 중 새 scene 의 성분을
  제거하는 설계는 불가능하다. 대신:

  **채택 설계**: 잔차화는 **offline 에서 방향 r̂ 를 뽑는 데만** 쓰고, 추론
  시에는 그 **고정 벡터 하나만** 적용한다. 새 scene 전이가 필요 없다.
  (문서에 이 결정을 명시할 것 — 나중에 "scene 제거가 안 되니 G3 불가"로
   잘못 결론내는 것을 막는다.)

[5-2] 연산자는 아직 확정하지 않는다. exp5-3 에 요청한 setM β sweep
  (exp5-1_to_exp5-3_beta_sweep_request.txt) 결과와 §4-2 차원 판정이 나온 뒤
  사전 등록 규칙대로 고른다.

[5-3] **SAE 존폐 판단을 명시적으로 할 것.** §2-B 를 근거로,
  (a) SAE 를 계속 쓸 것인가, (b) 선형 부분공간 제거로 갈아탈 것인가,
  (c) SAE 를 다른 용도(§4-2 가 부분공간이라 나오면 feature 집합 연산자)로만
  남길 것인가 — 셋 중 하나를 32 문서에 결론으로 적을 것. 미루지 말 것.

═══════════════════════════════════════════════════════════════════
6. 하지 말 것
═══════════════════════════════════════════════════════════════════

- 전체 scene 값만 적고 unseen 값을 생략하지 말 것(§3-1).
- "G2 통과" 를 "scene 제거 가능" 또는 "steering 가능" 으로 확대하지 말 것.
  read ≠ write 는 여전히 미검증이고, exp5-3 의 write 는 실패했다(SR 0.344→0.025).
- SAE 열세(§2-B)를 각주로 처리하지 말 것.
- mixer 를 이번 통과에 포함시키지 말 것(§3-3).
