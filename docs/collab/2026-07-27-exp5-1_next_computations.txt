0. 배경 — 왜 지금 이걸 하나
═══════════════════════════════════════════════════════════════════

G3(실제 steering)는 이미 한 번 실행됐고 실패했다: exp5-3 setM_within_permanent
β=1.0 → SR 0.344 → 0.025, 해악 52/55. 육안으로도 로봇이 확연히 떨린다.
그 앞으로 exp2·exp3·exp4-1 세 라운드가 전부 null. **밀기 쪽 전적 3무 1패.**

exp5-1 의 G3 가 그 반복이 되지 않으려면 세 가지가 달라야 한다:
  ① 방향   — scene 잔차화로 뽑은 방향이 실제로 더 나은가?          → 계산 A
  ② 연산자 — 실패 신호가 1차원인가 부분공간인가?                    → 계산 B
  ③ 범위   — 어느 토큰을 밀어야 하나?                              → 계산 C
셋 다 미확정 상태로 G3 를 돌리면 exp5-3 이 방금 한 것을 그대로 반복한다.

(용량 β 는 exp5-3 에 sweep 요청 — exp5-1_to_exp5-3_beta_sweep_request.txt)

1. 계산 A — scene 간 방향 일관성 (cos) 잔차화 전/후  ★최우선
═══════════════════════════════════════════════════════════════════

**질문**: scene 성분을 제거하면 "실패 방향"이 scene 을 넘어 더 일관돼지는가?

**왜 최우선인가**: exp5-3 실측으로 scene 별 실패방향끼리 cos 평균이 **0.343**
이다(공통 성분이 소수). 이 값이 잔차화로 올라가지 않으면 **exp5-1 이 exp5-3
위에 더하는 것이 사실상 없다**(§5). G3 로 넘길 방향의 품질을 직접 재는 지표다.

**절차**
  1. 혼재 scene 13개 각각에서 within-scene 실패방향
       d_s = mean(fail episode vector) − mean(succ episode vector)
     episode vector 규약은 read 와 동일: 창 [0,38) 평균.
  2. 정규화 후 13개 방향의 **쌍별 cos** → 평균·중앙·최소·최대.
  3. 세 조건에서 각각 계산:
       (a) raw
       (b) linear_between r16 잔차화 후   ← G2 최고 arm
       (c) SAE selective 제거 후          ← 비교용(열세 확인)
  4. token_agg 는 exp5-3 앵커 비교를 위해 **K·T 평균(=그쪽 방식)** 과
     **future 세그먼트** 둘 다 산출. (a)+K·T평균이 0.343 근처로 재현되면
     배관이 맞다는 확인이 된다 — 이 앵커 확인을 먼저 할 것.

**판정**
  · cos 평균이 뚜렷하게 상승(예: 0.34 → 0.5+)  → 잔차화가 방향을 개선했다.
    exp5-1 은 "더 나은 방향을 만드는 공정"을 소유한다 → G3 로 갈 실익 있음.
  · 거의 그대로                                 → 증분 없음 → §5 로.
  · 하락                                        → 잔차화가 신호를 깎았다.
    read AUROC 상승(0.80→0.90)과 상충하므로 원인 규명 필요.

═══════════════════════════════════════════════════════════════════
2. 계산 B — 실패 신호의 차원 (연산자 가족 결정)
═══════════════════════════════════════════════════════════════════

**질문**: 실패축이 1차원인가, 여러 방향이 필요한 부분공간인가?

**절차** (LOSO 유지 — 아니면 잡음을 재게 된다)
  1. 평소대로 within-scene LOSO 방향 r̂₁ 을 구하고 read AUROC 측정(기준).
  2. episode vector 에서 r̂₁ 성분 제거:  v' = v − (v·r̂₁)r̂₁
  3. **잔차 공간 안에서 방향을 다시 LOSO 로 fit** 해 r̂₂ 를 구하고 read 재측정.
  4. 3~4회 반복. 각 단계의 AUROC 와 순열 null z 를 기록.

**판정**
  · r̂₁ 제거 후 AUROC 가 null 수준으로 붕괴  → **1차원.**
    → 연산자는 방향-only 계열(고정 스텝 / 성분 제거)로 충분. 부분공간·conceptor
      ·SAE feature 집합은 불필요 — 이 경우 **SAE 노선을 접는 근거**가 된다.
  · 2~3개 제거해도 AUROC 가 유의하게 남음        → **부분공간.**
    → 다차원 연산자가 처음으로 정당해진다. SAE feature 집합이 후보로 부활.
      (단 선행연구상 DiT 는 단일 feature steer 시 출력 붕괴 — 집합 단위로.)

**주의**: 2단계에서 방향을 잔차 공간 밖(원래 fit)에서 가져오면 안 된다.
반드시 잔차 안에서 재추정하고 held-out scene 은 계속 제외.

3. 계산 C — 토큰 세그먼트별 실패축 (개입 범위 결정)
═══════════════════════════════════════════════════════════════════

**질문**: outcome 신호는 어느 토큰이 나르는가? scene 과 같은 토큰인가?

**절차**
  record 벡터를 세그먼트별로 나눠 같은 read 를 3번 돌린다:
    state  [0:1] / future [1:33] / action [33:49]
  각각 AUROC · 순열 null z · (계산 A 의) cos 일관성까지 산출.

**왜 중요한가**
  · G1 에서 **scene 은 future 토큰**에 있다고 나왔다(g2 의 token_agg_primary=future).
  · 만약 **outcome 은 action 토큰**에 있다면 → scene 과 outcome 이 토큰 축에서
    분리된다는 뜻이고, "future 는 잔차화하고 action 만 민다" 는 **깨끗한 개입
    설계**가 나온다. 이건 exp5-3 이 구조적으로 볼 수 없는 정보다(토큰 평균).
  · 떨림 저감과도 직결: exp4-1 실측에서 future 토큰만 미는 쪽이 permanent 대비
    jerk 를 0.29~0.91 배로 낮췄다. 미는 토큰을 좁히는 것 자체가 해악을 줄인다.

4. 연산자 사전 등록 결정표 (계산 B·β sweep 결과로 자동 결정)
═══════════════════════════════════════════════════════════════════

연산자 가족(같은 가족, 겨누는 곳만 다름):
    setM(현행)   h' = h − β(사영 − s)r̂        목표값 s 필요 ← s 의 33.7% 가 노이즈
    고정 스텝    h' = h − α r̂                 목표 없음, α 필요, 멈출 기준 없음
    성분 제거    h' = h − (h·r̂)r̂              목표=0, 파라미터 없음, 적응적
    부분공간     h' = h·M,  M = I − Σ r̂ᵢr̂ᵢᵀ    방향 여러 개

  계산 B = 1차원  &  β sweep 패턴 A(용량 과다)  → **성분 제거** 우선, 고정 스텝 차선
  계산 B = 1차원  &  β sweep 패턴 B/C(방향 무익) → 개입 계열 종결 보고
  계산 B = 부분공간                              → **부분공간 연산자**
                                                  (SAE feature 집합 또는 다중 r̂)
  어느 경우든 setM(setpoint형)은 기본 탈락 — s 추정이 부실하고 표적 scene 의
  라벨된 성공판을 요구해 배포 일반성이 없다.

★ 결과를 본 뒤 유리한 연산자를 고르지 말 것. 이 표를 32 문서에 먼저 박고 갈 것.

5. exp5-1 · exp5-3 역할 정리 (계산 A 결과로 판단)
═══════════════════════════════════════════════════════════════════

SAE 가 선형에 열세로 밝혀진 뒤, exp5-1 에 남은 것은 "선형 부분공간 제거 +
mean-diff 방향" 이라 exp5-3 도구와 상당 부분 겹친다. 같은 데이터·같은
프로토콜·같은 layer 를 쓰면서 **raw 기준선이 서로 다르다**(exp5-3 0.847 vs
exp5-1 0.800, 토큰 집계 차이). 이 상태를 방치하면 숫자가 계속 어긋난다.

  · 계산 A 에서 cos 상승 확인 → exp5-1 = **read·방향 도출 담당**,
    exp5-3 = **write·SR eval 담당**. 파이프라인 앞뒤로 분업, 중복 read 분석 중단.
  · cos 상승 없음 → exp5-1 의 증분이 없다. **exp5-3 으로 합치는 것을 사용자에게
    권고**하고, exp5-1 은 토큰 해상도 분석(계산 C)만 남긴다.

어느 쪽이든 **raw 기준선 불일치는 계산 A 의 앵커 확인(§1-4)으로 해소할 것.**
