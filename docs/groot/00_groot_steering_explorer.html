GR00T Latent Steering Explorer

GR00T N1.6/N1.5, LeRobot/native, RoboCasa365, ZMQ/HTTP, SAFE feature collection, COAST/conceptor latent steering 흐름을 한 파일에서 따라가기 위한 repo-local HTML 지도.

한 화면 구조

전체 흐름은 profile에서 시작해 server/model loader, eval 또는 collector client, observation adapter, policy inference, action adapter, env.step() 또는 SAFE artifact writer로 내려간다.

1. Profile
configs/checkpoints/*.yaml가 checkpoint 위치, base_model, image/state/action layout, n_action_steps, GR00T embodiment를 고정한다.
2. Server
scripts/serve/groot.py는 native GR00T N1.6, scripts/serve/lerobot.py는 LeRobot policy wrapper를 FastAPI로 serve한다.
3. Transport
HTTP는 VLAClient JSON/base64 schema, ZMQ는 GR00T native observation dict와 PolicyClient protocol을 쓴다.
4. Latent Steering
SAFE collection은 action과 hidden state를 함께 저장하고, steering은 feature server hook에서 hidden state를 변환한다.

용어

native: LeRobot wrapper를 거치지 않고 Isaac-GR00T 서버/정책을 직접 쓰는 경로. 이전 대화에서 말한 naive는 이 문서에서 native로 표기한다.

unified HTTP language: observation.images.left, action.eef_pos 같은 project FastAPI 계약.

GR00T native language: video.res256_image_side_0, action.end_effector_position 같은 Isaac-GR00T/RoboCasa key.

SAFE feature: GR00T inference 중 action-token latent를 캡처해 steering 분석과 conceptor fit에 쓰는 hidden state.

Latent Steering 핵심 수식

이 repo의 steering 수식은 src/conceptor/와 scripts/serve/steering_hooks.py에 구현돼 있다. 현재 관심 축은 CP threshold가 아니라, hidden state를 성공 부분공간 쪽으로 직접 변환하는 latent intervention이다.

1. Conceptor

C = R (R + α-2I)-1

R은 activation correlation, α는 aperture다. 구현: src/conceptor/core.py::compute_conceptor.

2. Success / Failure Contrast

Csteer = Csuccess ∧ ¬Cfailure

성공 부분공간은 유지하고 실패 부분공간은 억제하는 contrastive conceptor다. 구현: contrastive_conceptor().

3. Steering Gate

M = (1 - β)I + β Csteer,   h′ = h MT

β=0이면 원본, β=1이면 full conceptor projection이다. 구현: build_steering_matrix(), apply_steering().

4. Layer / Aperture Diagnostics

q(C) = tr(C) / d
overlap(Ca, Cb) = tr(CaCb) / sqrt(tr(Ca2) tr(Cb2))

Quota는 부분공간 크기, overlap은 두 conceptor의 겹침이다. 구현: src/conceptor/analysis.py.

SAFE Feature 정의

DiT pre-velocity slice

Z = model_output[:, -Hmodel:, :][:, :Hexport, :]
hidden_states ∈ RB×K×H×D

GR00T N1.6 RoboCasa 기준으로 model_action_horizon=50, valid_action_horizon=16이며, K는 denoising step 수다. 구현: src/policies/groot/safe_features.py.

Feature axes

valid: ["denoising_step", "valid_action_step", "feature_dim"]
all:   ["denoising_step", "model_action_token", "feature_dim"]

Steering 연구 흐름

Phase 0. SAFE detector baseline
Detector/CP는 과거 baseline으로 남긴다. DiT pre-velocity feature + LSTM detector는 unseen에서 chance에 가까웠고, 현재 주력 방법은 latent steering이다.
Phase 1. COAST / DiT-only conceptor
DiT 32-layer COAST 재현에서 평균 ΔSR ≤ 0. Layer quota도 중간층 peak 없이 약했다.
Phase 2. NOTALL 해석
GR00T에는 goal semantics(VL)와 motor program(DiT)이 분리된다는 가설을 적용. 기존 실패는 DiT-only였기 때문일 가능성이 커졌다.
Phase 3. VL + DiT aligned capture
VL seq-mean-pool과 DiT 7-layer per-token feature를 같은 rollout에서 수집하고 pathway separation을 비교했다.
Phase 4. Type-matched steering target
VL-dominant task에는 VL steering, DiT-dominant task에는 DiT steering을 비교하는 것이 다음 축이다.

현재 결론

  • VL은 t≤8에서 더 이른 실패 신호를 낸다.
  • DiT는 t≥12에서 motor failure task에 강해진다.
  • SlideDishwasherRack은 VL AUROC 0.931로 goal-type failure 후보가 강하다.
  • OpenCabinet/OpenDrawer/PnP는 DiT-dominant motor-type failure 후보가 강하다.

다음 구현/실험 축

  • fit_conceptor_steering.py에 --pathway vl 지원.
  • feature_server.py에서 --steering-pathway vl로 VL hook 적용.
  • eval_steer_pathways.sh로 baseline + VL β + DiT β 비교.
  • B/C quadrant video를 정성 검증해 goal/motor 해석을 확인.

주의할 claim

  • Action smoke는 SR 검증이 아니다.
  • HTTP parity와 ZMQ baseline은 별개 claim이다.
  • 길이 confound는 succ/fail latent 분석에서 반드시 통제해야 한다.
  • 시각화 결과는 geometry 진단이고, steering 성능 주장은 rollout ΔSR이 필요하다.
