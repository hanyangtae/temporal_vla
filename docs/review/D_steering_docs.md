## 0. 이 트랙의 목표

D는 코드 스테이지가 아니다. 목표는 두 가지다.

1. **결과 문서를 읽어 "무엇이 종결됐고 무엇이 살아있는지" 확정한다.** 이것이 S1~S9 전체의
   keep/archive 판정 근거가 된다. 코드를 보며 "이거 아직 쓰나?"를 매번 추측하지 않기 위함.
2. **소모품을 걷어낸다.** 계획·핸드오프 문서는 라운드가 끝나면 죽는다. 46개 중 절반 가까이가 그렇다.

## 4. 판정 시 갈리는 지점

제 판단으로는 아래 넷이 실제로 고민이 필요한 항목이고, 나머지는 유형에 따라 기계적으로 갈린다.

1. **`11_phase4`(1421줄)** — 종결된 라운드의 계획이지만 실행 로그가 붙어 있다. 로그에 재사용할
   사실(seed 선정 기준, 수집 절차)이 남아 있는지가 `archive` / `수정`(로그만 발췌) 을 가른다.
2. **`13_lab_meeting_ppt_notes`(371줄)** — 06-23 발표는 끝났다. Part A(현재 덱)·Part B(원본 아웃라인)
   구조가 중복인데, 그림↔수치 출처 매핑은 다음 발표에서도 쓸 수 있다.
3. **NOTICE 2개** — 전달 목적은 소비 완료. 다만 `NOTICE_scene_feasibility`가 담은 지식
   (fixture seed에 물리적으로 불가능한 scene이 섞임)은 **여전히 유효**하다. 통지문을 지우면
   그 지식도 같이 사라진다 → 지식만 다른 문서로 옮길지 판단 필요.
4. **`26_closefridge` / `27_standmixer` 라벨러 명세** — S2(라벨링)로 옮기자고 설계에 적었으나,
   CloseFridge는 exp4에서 탈락한 task다. 명세를 코드 옆으로 옮길지, 그냥 보존할지.
