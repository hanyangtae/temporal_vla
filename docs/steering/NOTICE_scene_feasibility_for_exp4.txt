[1] 무슨 일이 있었나

OpenStandMixerHead 스모크(18판) 실패 영상을 사람이 눈으로 확인하다가, 한 판(seed 100010)
이 "정책이 못 여는" 게 아니라 **믹서 머리가 위쪽 선반에 물리적으로 막혀서** 못 여는
scene 이라는 것을 발견했다. 라벨러 phase 로는 contact-head ↔ lift-open ↔ push-down 이
계속 진동하는 모습이라 "재시도 실패" 처럼 보이지만, 실제로는 열 공간 자체가 없다.

이런 판은 latent 실패가 아니다. succ/fail 대조 conceptor 의 failure 클래스에 섞이면
"실패 방향"이 아니라 "scene 기하"를 학습한다. exp3 까지 우리를 괴롭힌 scene confound
와 같은 계열의 오염원이고, 더 나쁜 건 **어떤 steering 으로도 구제 불가능한 판**이라
rescue 실험의 분모를 조용히 갉아먹는다는 점이다.

[2] 걸러내는 방법 (정책 무관, CPU only, seed 당 수 초)

  scripts/safe/groot_n15/robocasa/analyze/mixer_scene_feasibility.py

reset 직후 로봇은 건드리지 않고 **대상 관절만 0→1.0 으로 스윕**하면서, 움직이는 body 의
geom 이 (그 fixture 자신·로봇 이외의) 외부 geom 과 접촉하는 지점을 찾는다.
접촉 없이 도달 가능한 최대 정규화값 = q_max_feasible.

  q_max_feasible < 성공임계  →  그 seed 는 어떤 정책으로도 성공 불가 → 제외

OpenStandMixerHead 성공임계 = head > 0.99.

실행 (robocasa 컨테이너):
  docker exec -e MUJOCO_GL=egl \
    -e PYTHONPATH="/temporal_vla/src/policies/Isaac-GR00T:/temporal_vla/src/benchmarks/robocasa:/temporal_vla/src/benchmarks/robosuite:/temporal_vla:/temporal_vla/scripts/safe/groot_n16/robocasa/collect" \
    robocasa python /temporal_vla/scripts/safe/groot_n15/robocasa/analyze/mixer_scene_feasibility.py \
    --seeds 100000-100099 --out /temporal_vla/outputs/.../scene_feasibility.json

[3] 실측 결과 (seed 100000-100011, 12개)

  100000~100009, 100011 : q_max = 1.000  OK
  100010                : q_max = 0.575  BLOCKED (shelves_left_group_level0_shelf)

  → 12개 중 1개(8.3%) 불가능. 100000-100099 전체 스캔은 아직 안 했다.

교차검증: seed 100010 rollout 이 실제 도달한 최대 head 값 = 0.596.
기하 상한 0.575 와 사실상 일치 → 정책은 천장까지 밀어붙였고 더 갈 데가 없었던 것.
(rollout 이 상한을 살짝 넘는 건 접촉 후 밀어내며 생기는 탄성 변형. 판정에는 무영향.)

[4] 왜 이 필터는 편향을 만들지 않나 (confound-audit 대응)

- 정책·체크포인트·steering arm·chunk 설정과 무관하다. **seed 만의 함수**다.
- 따라서 base/perm/gated 모든 arm 에 동일한 seed 집합이 적용된다 → arm 간 비교 불변.
- 제외는 fit·eval **양쪽 모두**에서 동일하게 해야 한다. 한쪽만 걸면 그게 새 confound다.
- 제외 seed 목록과 q_max 값을 manifest/NPZ meta 에 기록해 사후 감사 가능하게 할 것.

[5] 한계 — 알고 쓸 것

- **정적·관절만** 검사다. 그리퍼가 fixture 를 잡은 상태로 움직이다 그리퍼 자체가
  선반에 걸리는 경우는 못 잡는다 (로봇 geom 을 접촉 판정에서 제외했다 — reset 시
  로봇이 근처에 있으면 오탐이 나서). 필요하면 "그리퍼 포함" 변형을 플래그로 추가.
- 스크립트는 현재 **StandMixer 전용**이다 (`env.stand_mixer`, `_joint_names["head"]`).
  다른 fixture 태스크로 옮기려면 ① fixture 참조 ② 관절 이름 ③ 움직이는 body 이름
  ④ 성공임계 네 개만 바꾸면 된다. 우선순위:
    - CloseFridge: fxtr._fridge_door_joint_names (도어별로, 임계 ≤0.005, 다짝 전부)
    - OpenDrawer : env.drawer 관절 (임계 ≥0.90 계열)
  drawer/fridge 에도 같은 오염이 있는지는 **아직 확인 안 했다.** exp2·exp3 의 drawer/
  ppcc 결과에 이 오염이 얼마나 섞였는지도 미확인 — 사후 스캔 가치 있음.
- seed 당 **fresh 프로세스** 필수. 한 프로세스에서 gym.make 를 연속 호출하면 두 번째
  부터 scene 이 오염된다 (docs/steering/18 §2 실증). 스크립트는 이미 그렇게 되어 있다.
