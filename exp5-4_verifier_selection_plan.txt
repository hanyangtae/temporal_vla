0. 한 줄 주장
═══════════════════════════════════════════════════════════════════

**같은 task 에서 학습한 t=0 활성 축으로, 처음 보는 scene 의 denoise 노이즈 draw 를
실행 전에 골라 SR 을 올릴 수 있다.**
  drawer_right : 0.344 → **0.650** (Δ+0.306), 혼재 scene 에서 top-1 적중 **13/13**
  exp41_mixer  : 0.688 → **0.850** (Δ+0.162), 혼재 scene 적중 **12/15**

같은 축을 **밀기(steering)** 에 쓰면 Δ+0.000 인데, **고르기(selection)** 에 쓰면 위 값이다.
exp5-4 는 이 관찰을 **인과로 검증**하고 **task·layer 로 일반화**하는 라운드다.

★헤드라인 주의 (검토 반영 2026-07-28, exp5-3 세션):
  위 13/13·+0.306 은 **seed-공유 부풀림 가능성이 있는 상한**이다. 같은 inference_seed 는
  같은 머신에서 **수치적으로 동일한 노이즈 draw** 를 낳는다(serve 가 매 호출
  torch.manual_seed(inference_seed+record)). 사후 순위의 방향 fit 은 scene 만 제외했지
  seed(0~7e6)는 다른 scene 들과 공유하므로, drawer 처럼 seed 주효과가 실재하는 cell
  (seed 별 SR 0.15~0.65, 무효과 기대 대비 1.67배)에서는 순위가 "이 활성이 나쁘다"가
  아니라 "**이 노이즈는 다른 scene 에서 이미 나빴다**"의 암기일 수 있다. Phase A(새 seed)
  가 정확히 이걸 가른다 — 기대치는 13/13 재현이 아니라 t=0 seed-out 분리도(0.712) 수준
  으로 낮춰 잡을 것. 0.34→0.5 대만 나와도 주장은 성립한다.

1. 왜 밀기가 아니라 고르기인가 — exp5-3 이 소진한 것
═══════════════════════════════════════════════════════════════════

setM(setpoint mean-diff) 개입, drawer_right, A0 앵커(40판) 대비 paired:

  arm                       n     SR     A0    Δ판    구제      해악      p     jerk(A0비)
  β=1.0 full               40  0.000  0.350   −14   0/26   14/14   <0.001      —
  β=0.5 full               40  0.225  0.350    −5   1/26    6/14    0.125    1.19x

  (2026-07-28 갱신: fut_b05 추가·jerk 열 추가. 위약 setM_within_pl_fut_b10 진행 중 —
   fut 의 구제3/해악3 churn 이 방향 특이적인지 판정 후 이 표를 최종화할 것.)

소진한 축 3개:
  · **용량**: β 1.0→0.2 로 해악은 단조 감소(95%→21%)하나 **구제는 어느 용량에서도 ~0**
    (누적 1/133). "β↓ → base 수렴" 이지 "base 초과" 가 아니다.
  · **개입 토큰**: action 세그먼트가 떨림의 원인. 같은 β=1.0 에서 full 은 해악 14/14
    (정책 전멸), future-only 는 3/14. 근거 — 세그먼트 단독 분리도 state 0.667 /
    **future 0.727** / **action 0.556**(거의 우연)인데 action 토큰이 곧 출력 chunk 로
    디코딩된다. jerk 실측: β=0.5 가 β=0.2 보다 1.19배(길이통제, 짝 28/30).
  · **방향 품질**: cross-scene 방향은 실은 **scene 난이도 방향**(cos 0.92~0.93). exp5-3 은
    within-scene 방향으로 read AUROC 를 0.627 → 0.878 로 올렸으나 **write 결과 불변**.
    → "fit 이 나빠서 안 됐다" 는 변명이 제거됨.

구조적 이유(가설): **실패는 실행 중에 자라나 교정 가능한 것이 아니라 t=0 에 추첨된다.**
  · t=0(관측이 scene 안에서 완전 동일·로봇 미이동) 에 이미 분리: drawer L12 0.729,
    seed 까지 held-out 시 L0 0.712(z 2.9); mixer 0.636~0.639(p=0.005)
  · L0(첫 DiT 블록)에서 이미 최고 수준: drawer 0.858 / 부호 13/13
  · exp4-1 에서 **방향 없는 noise_resample 이 거의 전 cell 최고 구제율**(bread .37 beer .43)
  → steering 은 원인이 아니라 결과를 건드리고 있었다. 레버리지는 **샘플링 시점**에 있다.

선택이 밀기의 약점 3개를 구조적으로 회피한다:
  ① **앵커 불요** — 순위는 후보끼리 상대 비교라 scene 오프셋에 불변. steering 을 막던
     setpoint 문제(신뢰도 0.708, 분산의 34% 가 추정 노이즈, 손잡이 기하와 무상관)가 소멸.
  ② **떨림 없음** — 활성을 건드리지 않는다.
  ③ **해악 구조적 0** — 실행 전에 고르므로 성공 판을 망가뜨릴 경로가 없다.

3. ★아직 성립하지 않은 것 (exp5-4 가 풀 것)
═══════════════════════════════════════════════════════════════════

[3-1] **사후 선택이다. 인과가 아니다.**
  8판을 **이미 굴려 결과를 알고** 순위를 매겼다. 지금 값은 **선택 가능성의 상한**이다.
  인과로 만들려면: 새 노이즈 → t=0 점수 → 고른 것만 실행 → SR 재측정.

[3-2] **전패 scene 은 못 구한다 (천장).**
  drawer 7/20(35%) 은 8개 draw 전부 실패 → 무엇을 골라도 실패. k 를 8까지 늘려도
  drawer top-1 은 0.650 에서 안 오른다. mixer 는 전패 1개뿐이라 k=8 에서 0.950 까지 간다.
  → **"성공 가능한 scene 에 한해서" 를 반드시 병기.**

[3-3] **task 를 넘지 못한다.**
  drawer→mixer +0.113 / mixer→drawer +0.106  vs  자기 cell +0.306 / +0.162.
  공통 성분은 있으나 이득의 대부분은 task 별 방향에서 온다 → task 마다 160판 수집 필요.

[3-4] **표본 13~15 scene.** drawer 13/13 은 강하나 scene 수가 적고 mixer 는 12/15.

[3-5] **자명한 특징으로 설명되는지 미확인.**
  t=0 에 관측이 동일하므로 점수는 노이즈의 함수다. 그 함수가 **학습된 축인지, 아니면
  단순 크기 지표(활성 노름·첫 action 크기)인지** 안 갈랐다. 이게 안 갈리면 기여가 0 이다.

4. exp5-4 설계
═══════════════════════════════════════════════════════════════════

★게이트 순서 (검토 반영): Phase A 는 **drawer 1 cell(160판, home ~3h)로 먼저 끊고**,
  §5 primary 통과 시에만 Phase B(task×layer) 착수. capture ON 이면 +~97GB — home 원본
  보존 + 승준 pull(mixer_sm_pull.sh 패턴, home 직결 불가라 승준 측 pull) 계획을 수집 전에
  잡을 것. Phase D 는 기존 데이터로 즉시 가능하므로 A 수집과 병렬 권장.

Phase A — **인과 검증** (필수, 다른 것보다 먼저)

  수집: 기존 20 scene × **새 inference_seed 8종**(8e6~15e6, fit 에 한 번도 안 쓴 값)
        = 160판/cell, capture ON. drawer_right 먼저.
  점수: 방향은 **기존 수집분(0~7e6)** 으로만 fit — 새 수집분은 방향에 전혀 미기여.
        새 판의 record 0 활성으로 점수 → scene 별 순위.
  arm(사후 집계로 분리, 추가 rollout 불필요):
    · **select-top1**  각 scene 1등만 채택 → SR
    · **random**       각 scene 무작위 1개(=base, 8판 평균) ← **위약 역할**
    · **select-worst1** 각 scene 꼴찌 채택 ← **음성 대조**(base 아래여야 함)
  판정: select-top1 > random > select-worst1 이면 방향이 인과적으로 작동.
        McNemar(scene 단위 20쌍) + 순열(각 scene 내 순위 무작위화).
  ★비용 주의: 위 설계는 8판을 다 굴린 뒤 사후 집계다(= 상한 재확인 + 새 seed).
    **진짜 배포형**(후보 forward k회 → 1개만 실행)은 Phase C.

Phase B — **task × layer sweep**

  task: drawer_right(보유) · mixer(보유) · **drawer_left**(신규, left 확정 seed 138종 보유)
        · ppcc_bread(신규, 선택) · 여력되면 CloseDrawer 등 fixture 계열 1종
        ※ beer 는 보류(실패 원인 이질·이벤트 검출기 불신 — 선행 문서 §6)
  layer: 캡처된 7종 전부(0,2,4,8,10,12,15)
  창: **record 0 단독** primary, 앞 8 record secondary
  산출 표: task × layer → top-1 SR, Δ, 혼재 scene 적중률, 최악1 SR
  기대 효용: layer 프로파일이 task 마다 다른지(분리도는 drawer L12 / mixer L2 로 달랐다),
             선택 이득도 같은 패턴인지.

Phase C — **배포형 비용·이득** (Phase A 통과 시)

  절차: 새 scene 에서 후보 k개 노이즈 → 각 **첫 inference 만** 실행(행동 안 함) →
        점수 → 1등 seed 로 본 rollout 실행 → SR 측정.
  측정: k=2,4,8 별 SR 과 wall-time. 후보 1개당 forward 1회이므로 비용은 rollout 대비 미미.
  대조: 같은 k 에서 무작위 1개 실행(= base).

Phase D — **자명 특징 대조** (§3-5, CPU 만, 즉시 가능)
  같은 순위 절차를 아래 점수로 반복해 학습된 축과 비교:
    · record 0 활성 L2 노름 · 첫 action chunk 크기 ‖a‖ · action 변화량
    · 무작위 방향(이미 0.492 로 무효 확인)
    · (검토 반영) **task-기하 휴리스틱**: 첫 action chunk 의 목표 방향성 — 예: eef 이동
      벡터와 (손잡이 − eef) 방향의 cos. 활성 없이 action 만 보고 고르는 가장 강한 자명
      baseline. 학습 축이 노름류만 이기고 이것에 지면 "활성이 기하를 재포장했을 뿐"이 된다.
  학습 축이 이들을 유의하게 이겨야 기여가 인정된다.

Phase E — **문헌 대조** (검토 반영, 수집 前 반나절)
  inference-time 후보 선택 계열 선행: V-GPS 류 value-guided action selection,
  best-of-N + verifier/reward-model 샘플링, diffusion policy 의 sample selection.
  우리 차별점 후보 = ① 외부 보상모델·가치함수 없이 **내부 t=0 활성**만 사용
  ② succ/fail 라벨의 offline within-scene 대조로 fit ③ 후보당 forward 1회(rollout 0회).
  이 세 가지가 선행에 이미 있으면 niche 주장 수위를 조정할 것.

7. 이 라운드로 답이 나오는 질문
═══════════════════════════════════════════════════════════════════

  Q1 t=0 활성으로 고른 draw 가 **실제로** 더 자주 성공하는가 (Phase A)
  Q2 그게 task 와 layer 를 넘어 재현되는가 (Phase B)

  Q4 학습된 축이 자명 지표보다 나은가 (Phase D)

  Q1 이 부정이면 exp5-3+5-4 로 **"이 축은 읽히기만 하고 어떤 방식으로도 SR 에 쓸 수 없다"**
  가 확정된다 — 그것도 명확한 결론이다(COAST 전제는 맞으나 결론이 안 따라온다는 증거).
